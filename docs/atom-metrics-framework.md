# Atom 商业业绩指标框架 v0.2

> 目的：为 Atom（智能硬件 + 软件订阅）搭建一套管理层可用的指标体系与数据看板。
> 状态：核心口径已对齐（见 §1 决议记录），进入指标字典细化阶段。

---

## 0. 先说结论

### 0.1 这套看板要回答的问题（v0.2 聚焦后）

| # | 问题 | 本质 | 一句话判据 | 状态 |
|---|---|---|---|---|
| Q1 | **卖得动吗？** | 硬件生意 | 出货量、激活率、渠道结构、退货率 | ✅ 本期 |
| Q2 | **用得住吗？** | 产品价值 | 留存曲线是否 flatten（存在稳定的长期留存平台）| ✅ 本期，**重心** |
| Q3 | 赚得回吗？ | 商业模型 | LTV/CAC、回本周期 | ⏸ **暂缓**（业务方决定），框架保留占位 |

**Q2 是核心。** 硬件公司最典型的失败模式不是卖不动，而是"卖得动但用不住"。注册/活跃/上课/运动四块数据真正要支撑的就是这个判断。

### 0.2 North Star

- **NSM：周运动活跃账号数 WAU-Workout**
  = 自然周内至少完成 1 次「有效训练」的**账号**数。
  （变现侧 NSM 随 Q3 暂缓，后续启用时补充"活跃付费订阅数 / MRR"。）
- 配套健康度：**运动转化率 = WAU-Workout / WAU-开机**（开了机的人里有多少真的练了）。

### 0.3 一条主线：业务漏斗（v0.2 版）

```
发货 → 售出 → 设备配对激活 → 首次有效训练 → 形成习惯 → 长期留存 → (订阅转化，暂缓)
        ↓          ↓               ↓             ↓            ↓
      销售       激活率        Aha 前置       首月频次     W4/W12 留存
```

App 注册作为激活前置的参考段（见 §3.1），不作为主漏斗节点。

## 1. 决议记录（2026-08-18 对齐）

| # | 议题 | 决议 |
|---|---|---|
| D1 | **统计主键** | **账号（人）为主键**。同一账号可绑定多台 Atom。活跃、留存、cohort、频次一律按 `user_id` 去重；`device_id` 用于激活计数、硬件批次分析、设备健康。 |
| D2 | **注册口径** | App 注册与机器绑定激活是两个数字，高度相关但不相等。**以机器配对激活为主口径**；App 注册作为参考曲线和激活前置漏斗段。 |
| D3 | **Cohort 粒度** | **周 cohort + 月 cohort 并行**。前期以周为主（配合每周 OTA 节奏），月 cohort 看长期趋势。 |
| D4 | **地区维度** | 设备分**国际版 / 中国版**两条产品线，作为一级维度；国际版下钻国家/地区。所有指标支持此切分。 |
| D5 | **离线行为** | 离线可开机使用（浏览、拍照），**不能上课**。开机事件本地 log、联网后补传（有滞后）。因此三层活跃 = 开机 → 联网 → 运动，且**运动活跃天然 ⊆ 联网活跃**。 |
| D6 | **有效训练定义** | **≥1 个完整组（set）或 ≥1 分钟训练**，即算一次有效训练。组数与时长作为"活跃质量"指标在有效训练内部再看。 |
| D7 | **时区口径** | **以美国时区为准定义"日"**（全球统一日界）。⚠ 待确认：PT 还是 ET（建议 PT，见 §2.3）。 |
| D8 | **LTV/CAC** | 暂缓。变现模块保留占位，不进本期交付。 |

### 决议带来的三个连锁影响（需要知晓）

1. **账号主键 + 一号多机** → 需要维护 `账号-设备` 绑定关系表（含换绑/解绑历史）。活跃按账号去重后，另出"户均设备数、多机账号占比"作为辅助指标；设备级活跃仍保留，供硬件团队用。
2. **开机事件补传滞后** → 开机活跃（L1）的近几天数字会持续回填变化。报表必须支持回溯重跑，页面标注"近 N 日未定稿"；联网（L2）和运动（L3）不受影响（上课必须在线）。
3. **美国日界 × 中国版设备** → 中国用户的自然使用日会被美国日界从下午切开（PT 午夜 = 北京 15/16 点），中国版的 DAU 波形会有相移、单日数字与"北京时间的一天"对不上。管理层全局口径统一按美国日没问题，但**分析中国版用户行为时建议提供北京时间辅助视图**，避免误读。

## 2. 全局口径约定

### 2.1 主键体系（双轨）

| 轨 | 主键 | 适用指标 |
|---|---|---|
| **账号轨（主）** | `user_id` | 活跃（三层）、留存、cohort、训练频次、分层、（未来）订阅 |
| **设备轨（辅）** | `device_id` | 累计/新增激活、激活率、设备健康、固件/批次分析 |

连接两轨：`bridge_user_device`（绑定关系 + 生效区间），设备活跃事件通过它归属到账号。
边界规则（建议）：
- 一台设备被多个账号先后绑定：事件按**事件发生时的绑定关系**归属。
- 同一账号多台设备同日活跃：账号级活跃只计 1（去重），设备级各计各的。

### 2.2 地区维度（一级维度）

```
product_line:  CN（中国版） | INTL（国际版）
region:        CN → 中国；INTL → 国家/地区（US, JP, DE, ...）
```

- 所有看板、报表、cohort 默认支持 `product_line` 切分，INTL 内支持国家下钻。
- 两条产品线的内容库、订阅定价、渠道可能都不同，**默认不做简单合并对比**，合计数仅在高管总览展示。

### 2.3 时间口径

- **日界：美国时区统一定义**（待确认 PT/ET；建议 **America/Los_Angeles**——若公司总部在西海岸，运营复盘的"昨天"与团队直觉一致；夏令时随之切换并在指标字典中记录切换日）。
- 周：ISO 周（周一起算），同样按美国日界。
- MAU 用滚动 28 天避免月份天数锯齿；自然月版本供财务。
- 中国版用户行为分析提供北京时间辅助视图（见 §1 连锁影响 3）。

### 2.4 数据定稿

- 开机（L1）事件有补传滞后：近 N 日（待 R3 确认）数据标注"未定稿"，每日重跑回填。
- 联网（L2）/运动（L3）为在线行为，T+1 即定稿。

## 3. 模块一：注册与激活

### 3.1 两条注册曲线 + 一个前置漏斗

| 指标 | 主键 | 定义 | 角色 |
|---|---|---|---|
| **累计配对激活设备数** | device | 历史上首次完成绑定激活的唯一设备数 | ★ 主口径，分 gross/net（扣退货） |
| 新增激活设备 | device | 按 `first_activation_date` 归属，终身只计一次 | ★ 主口径 |
| App 注册账号数（累计/新增） | user | 完成 App 账号注册 | 参考曲线 |
| 已绑定激活账号数 | user | 至少绑定 1 台已激活设备的账号 | 账号轨的"注册"基线，cohort 分母 |

**前置漏斗**：`App 注册 → 完成绑定激活` 的转化率与时延。
两个数的差值有两种成分：买前先下 App 研究的潜在用户（好事，是销售线索池）和收到货但绑定失败/放弃的用户（坏事，开箱体验问题）。按"注册后是否 7 天内绑定"拆开看。

### 3.2 激活健康指标

| 指标 | 定义 | 备注 |
|---|---|---|
| 激活率 | 累计激活设备 / 累计售出设备 | 健康区间通常 >85%；分 product_line 看 |
| 激活时延 | 购买/发货 → 首次激活（中位数 + P90） | >30 天长尾单独拉名单 |
| 首次绑定成功率 | 绑定流程进入 → 完成 | 开箱体验直接度量 |
| 已售未激活存量池 | 售出未激活的设备数及账龄 | 已花 CAC 零价值的资产，召回目标 |
| 户均设备数 / 多机账号占比 | 绑定设备数 / 账号 | 一号多机的规模；多机账号往往是最忠诚用户或 B 端场景，值得单看 |

### 3.3 拆分维度

`product_line`（一级）、国家/地区、渠道、SKU、固件版本、促销活动。

## 4. 模块二：活跃指标

### 4.1 三层活跃（决议 D5 版）

按账号去重；设备级同口径另存，供硬件团队。

| 层级 | 名称 | 定义 | 备注 |
|---|---|---|---|
| **L1** | 开机活跃 | 当日（美国日界）账号名下任一设备有开机/唤醒/物理交互 | 可离线产生，补传后回填，近 N 日未定稿 |
| **L2** | 联网活跃 | 当日账号名下任一设备与云端有有效心跳/同步 | T+1 定稿 |
| **L3** | 运动活跃 | 当日完成 ≥1 次有效训练（D6 定义） | 上课必须在线 → **L3 ⊆ L2**；North Star 基础 |

**诊断比值：**
- **运动转化率 = L3 / L1**：开了机却没练 → 被劝退（找课难、内容不合适、开机即弃）。产品体验最灵敏的探针。
- **联网健康率 = L2 / L1**：长期离线开机的占比 → 配网/网络环境问题；这部分用户"能用但享受不到内容更新"，也是上课转化的天花板。
- **静默账号**：近 28 天 L1 = 0 → 设备还在家里，可召回资产。

### 4.2 时间维度：3 × 3 矩阵

|  | DAU | WAU（滚动 7 日） | MAU（滚动 28 日） |
|---|---|---|---|
| L1 开机 | DAU-PowerOn | WAU-PowerOn | MAU-PowerOn |
| L2 联网 | DAU-Connected | WAU-Connected | MAU-Connected |
| L3 运动 | DAU-Workout | **WAU-Workout ← NSM** | MAU-Workout |

均按 `user_id` 去重、美国日界；每格支持 product_line 切分。

### 4.3 粘性与频次

- 健身产品 DAU/MAU 天然低（每周 3 次的模范用户也只有 ~43%），不与社交产品对标。
- 主用 **WAU/MAU** 与 **周均有效训练次数**；配**周频次分布直方图**（0/1/2/3/4/5+），均值会骗人。

### 4.4 用户分层（近 28 天，按账号）

| 分层 | 定义 |
|---|---|
| Power | ≥12 次有效训练（约 ≥3 次/周） |
| Regular | 4–11 次 |
| Light | 1–3 次 |
| Dormant | 0 次训练，但有开机/联网 |
| Churned | 0 次任何活跃 |

月度分层迁移用桑基/堆叠面积图。**Power 层的绝对数与占比是产品是否真正成功的最硬指标。**

## 5. 模块三：Cohort 与留存（周 + 月双粒度）

### 5.1 双粒度设计（决议 D3）

| 粒度 | 分组 | 用途 | 注意 |
|---|---|---|---|
| **周 cohort（前期主用）** | 首次激活的 ISO 周 | 快速反馈：本周激活的用户 W1/W2/W4 留存；对齐每周 OTA 节奏，看固件版本对新用户留存的影响 | 单周样本小、噪声大——**看趋势线不看单点**，样本 <100 的格子灰显 |
| **月 cohort** | 首次激活月 | 长期趋势、管理层汇报 | 需 3+ 个月数据后才有价值 |

- Cohort 起点 = **账号首次绑定激活日**（不是 App 注册日、不是购买日）。
- 留存口径：Classic（第 N 周/月内有活跃）为主；D1/D7/D30 精确日留存用于 onboarding 优化。
- 三层活跃各一条留存曲线；**L1 高但 L3 断崖 = 设备还在开，但不练了**（内容耗尽/进步停滞信号）。

### 5.2 下钻维度

| 维度 | 验证什么 |
|---|---|
| **product_line / 国家** | 中国版 vs 国际版的留存差异；国际版内不同市场 |
| **激活时固件版本 / 当前固件** | 每周 OTA 是否改善了新用户留存（周 cohort × 固件 是 OTA 效果评估的核心视图） |
| 渠道 | 用户质量差异 |
| **首周训练次数（0 / 1–2 / 3+）** | Aha Moment 候选，最重要的一条 |
| 首课类型（大课/短课/微课） | 哪种入门路径留存好 → 指导 onboarding 默认推荐 |
| 户均设备数 | 多机账号是否更忠诚 |

### 5.3 Aha Moment 分析

首周行为 × W12 留存相关性，找"跨过就留下"的阈值。健身品类经验上「首周完成 N 次训练」解释力最强。产出形如："首周 ≥3 次的账号 W12 留存 62%，<3 次仅 18%" → 下季度目标就是把首周 ≥3 次占比从 X% 提到 Y%。

### 5.4 Growth Accounting

周/月两个粒度：`活跃 = 上期活跃 + New + Resurrected − Churned`，看 **Quick Ratio = (New + Resurrected) / Churned**。
> Quick Ratio 逼近 1 而总量在涨 = 增长全靠新销量填流失坑，销售一放缓活跃盘就塌。放高管首屏。

### 5.5 复活

设备还在用户家里，沉默 ≠ 流失。看：复活率（沉默 ≥28 天账号的回归比例）、复活后二次留存、沉默时长分布。

## 6. 模块四：上课与运动指标

### 6.1 有效训练（决议 D6）

> **有效训练 = 单次训练会话中，完成 ≥1 个完整组（set），或训练时长 ≥1 分钟。**

- 组内动作次数下限的判定规则待定（R4：按课程定义 or 固定值）。
- 时长建议用**有效运动时长**（传感器判定实际在动的时间，扣除暂停/挂机）；若首期拿不到，先用会话时长并在字典中注明，后续切换时打口径变更标注。
- 门槛较低（1 组或 1 分钟）——这是刻意的：微课（one set/跳绳）本身就是习惯维持工具，不应被门槛排除。**质量不靠门槛把关，靠下面的"活跃质量"指标分层去看。**

### 6.2 活跃质量（有效训练内部再分层）

| 指标 | 定义 | 用途 |
|---|---|---|
| 单次组数分布 | 每次有效训练完成的完整组数（1 / 2–3 / 4+） | 区分"打卡式"与"认真练" |
| 单次时长分布 | <5 min / 5–15 / 15–30 / 30+ | 同上 |
| 周人均组数 / 周人均有效时长 | 按账号 | 总"运动量"趋势 |
| 深度训练占比 | 单次 ≥2 组 且 ≥5 分钟的训练占比 | 一个数概括质量结构 |
| 组完成率 | 完整组 / 开始的组 | 持续偏低 = 课程太难在劝退 |
| （待 R7）训练容量 Volume | Σ(reps × 阻力) | 有阻力传感则启用；"我在变强"是最强留存驱动 |
| 连续周 Streak | 连续 ≥1 次有效训练的周数分布 | Streak ≥8 周的用户几乎不流失 |

### 6.3 课型口径

| 类型 | 时长 | 代号 |
|---|---|---|
| 大课 Workout | 20–30 min | `WORKOUT` |
| 短课 Mini | 5–10 min | `MINI` |
| 微课 One Set / 跳绳 | 1–2 min | `MICRO` |

三类**分开统计，不做课次简单加总**；合并视角用有效时长/组数加权。**课型 Mix**（三类占比及其随生命周期变化）单独观察——新用户从微课起步逐渐进阶到大课，还是从大课退坡到微课再流失，是两个完全不同的故事。

### 6.4 上课指标清单

Session Starts / Completions、完成率（按课型、按单课）、平均完成度、人均课次、Time to First Workout（激活 → 首次有效训练）、首课完成率（与长期留存强相关）。

### 6.5 内容侧指标

- Top/Bottom 课程排行（开始数、完成率、复练率）；复练率高的才是真正的好内容。
- **内容库消耗速度**：已练内容 / 可用内容库，分 product_line（两边内容库不同）。高消耗用户（>70%）的规模与留存是订阅流失的头号前置信号。
- 新课上线采纳曲线。

### 6.6 核心运动指标

**周均有效训练次数（Workouts per Active User per Week）**——频次决定习惯、习惯决定留存。辅以**训练依从性 Adherence = 实际训练周数 / 激活以来总周数**（滚动 12 周），跨 cohort 可比的"坚持度"单一答案。

## 7. 模块五：变现与订阅 ⏸（暂缓，占位）

按决议 D8 本期不做 LTV/CAC。保留占位以便后续启用：订阅漏斗（attach → trial → paid → renew）、MRR、churn（主动/被动分开）、训练频次 × 续订率交叉分析。数据模型中 `fct_subscription_event` 表结构先预留，不建看板页。

## 8. 模块六：设备健康（支撑层）

在线率/掉线时长、固件版本分布、**OTA 覆盖率与升级成功率（每周 OTA 节奏下按周报告，与周 cohort 联动看效果）**、配网成功率及失败原因、传感器异常与 RMA（按批次/SKU/产线）、**数据完整性监控**（开机事件补传延迟分布、上报缺失率——直接决定 L1 与全部指标可信度）。

## 10. 数据模型与埋点

### 10.1 模型（v0.2 主键调整版）

**维度与桥接**
```
dim_user             user_id, signup_at, signup_source(app/device), region, product_line
dim_device           device_id, sku, product_line, firmware_version, channel, region,
                     sold_at, first_activated_at, is_returned
bridge_user_device   user_id, device_id, bound_at, unbound_at        -- 绑定历史，事件归属依据
dim_content          content_id, type(WORKOUT/MINI/MICRO), duration, product_line, ...
```

**事实表**
```
fct_app_registration        App 注册
fct_device_activation       设备配对激活（一台一行）
fct_device_power_on         开机事件（device_local_ts + server_received_ts 双时间戳，幂等 event_id）
fct_device_heartbeat        联网心跳
fct_workout_session         一次训练会话（核心）
fct_set                     一组一行（reps, resistance, is_complete）
fct_subscription_event      预留，暂不消费
```

**聚合底座**
```
agg_user_daily     ★ user_id × date(美国日界) 宽表：三层活跃 flag、各课型 session 数、
                     有效训练数、有效时长、完整组数、绑定设备数快照、product_line
agg_device_daily     device_id × date：设备级三层活跃、固件版本（给硬件团队与设备健康）
```

> 所有账号级活跃/留存/cohort/分层指标**只从 `agg_user_daily` 派生**——口径一致性的关键。

### 10.2 埋点要点

- 双时间戳（`device_local_ts` + `server_received_ts`）+ 幂等 `event_id`：离线补传的正确归日与去重。
- **`set_completed` 埋点是第一优先级**（有效训练 D6 定义直接依赖"完整组"）。
- 开机事件本地缓存上限与补传策略需与固件约定（决定 R3 的滞后窗口）。

## 12. 口径治理

1. **指标字典**为 single source of truth（业务定义、SQL、主键轨、时区、Owner、变更历史），看板数字可点入查看定义。
2. **口径变更走版本管理**：重算历史 + 图表标注（例如有效时长从会话时长切换到传感器时长的那一天）。
3. **未定稿显式标注**：L1 近 N 日受补传影响，与已定稿区分。
