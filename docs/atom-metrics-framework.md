# Atom 商业业绩指标框架 v0.4

> ⚠ **口径以 [`atom-data-dictionary.md`](atom-data-dictionary.md)（业务数据定义说明 v1.0）为准**——本文档保留战略框架与看板设计，指标定义细节已迁入数据字典。

> 目的：为 Atom（智能硬件 + 软件订阅）搭建一套管理层可用的指标体系与数据看板。
> 状态：核心口径已定案（§1 决议记录），订阅会员模块已纳入本期范围，进入指标字典细化阶段。

## 0. 先说结论

### 0.1 这套看板回答的三个问题

| # | 问题 | 本质 | 一句话判据 |
|---|---|---|---|
| Q1 | **卖得动吗？** | 硬件生意 | 出货量、激活率、渠道结构、退货率 |
| Q2 | **用得住吗？** | 产品价值 | 留存曲线是否 flatten（存在稳定的长期留存平台）——**重心** |
| Q3 | **愿意付费吗？** | 订阅生意 | 会员渗透率、Plus/Pro 结构、续费率 |

**Q2 是核心**：硬件公司最典型的失败模式不是卖不动，而是"卖得动但用不住"。Q3 建立在 Q2 之上——不训练的用户不会续费，先有留存才有会员生意。

### 0.2 North Star：一对指标互相牵制

- **NSM-1（价值）：WAU-Workout** = 自然周（PT 日界，ISO 周）内至少完成 1 次「有效训练」的账号数。
- **NSM-2（变现）：活跃付费 Pro 数** = 当日处于**自费** Pro 有效期内的账号数（不含赠送期；Plus 随设备终身免费，不是付费档）。
- 配套健康度：**会员渗透率** = 活跃付费会员 / 已绑定激活账号；**运动转化率** = WAU-Workout / WAU-开机。

### 0.3 业务主漏斗

```
发货 → 售出 → 设备配对激活 → 首次有效训练 → 形成习惯 → 长期留存 → 开通会员 → 续费/升级
        ↓          ↓               ↓             ↓            ↓           ↓          ↓
      销售       激活率        Aha 前置       首月频次    W4/W12 留存   渗透率    续费率/Pro占比
```

App 注册作为激活前置的参考段（§3.1），不作为主漏斗节点。

### 决议的连锁影响

1. **账号主键 + 一号多机** → 维护 `bridge_user_device` 绑定历史表；辅助指标"户均设备数、多机账号占比"。
2. **7 天补传窗口** → L1 报表近 7 日每日回填；页头标注"开机活跃近 7 日未定稿"；晚于 7 天到达的补传事件丢弃不入指标（防止定稿数据变动），但入原始表留档并监控其量级——若占比异常升高说明固件补传策略有问题。
3. **PT 日界 × 中国版设备** → PT 午夜 = 北京 15/16 点，中国用户自然使用日被从下午切开，中国版 DAU 波形有相移。全局口径统一按 PT；分析中国版用户行为时提供北京时间辅助视图。
4. **订阅数据接口独立** → 会员状态来自业务后端/计费系统，不走设备埋点管道。两边靠 `user_id` 关联，**账号体系一致性（R2）升级为订阅看板的前置条件**。收入金额（MRR 等）是否首期展示，取决于计费接口可得性（R9）。

## 2. 全局口径约定

### 2.1 主键双轨

| 轨 | 主键 | 适用指标 |
|---|---|---|
| **账号轨（主）** | `user_id` | 三层活跃、留存、cohort、训练频次、分层、会员/订阅 |
| **设备轨（辅）** | `device_id` | 累计/新增激活、激活率、设备健康、固件/批次分析 |

`bridge_user_device`（绑定关系 + 生效区间）连接两轨。设备被多账号先后绑定：事件按发生时的绑定关系归属；同账号多设备同日活跃：账号级计 1，设备级各计各的。

### 2.2 地区维度

`product_line`（CN / INTL）一级维度，INTL 下钻国家。内容库、定价、渠道两边不同，默认不做合并对比；合计数仅在高管总览展示。

### 2.3 时间口径（D7/D8 定案）

- **日界：America/Los_Angeles（PT）**，全球统一；夏令时随美国切换，切换日记录于指标字典。
- 周：ISO 周（周一起算，PT 日界）；MAU 用滚动 28 天，自然月版本供财务。
- 中国版行为分析提供北京时间辅助视图。

### 2.4 数据定稿（D8 定案)

| 数据 | 定稿规则 |
|---|---|
| L1 开机活跃 | 近 7 日未定稿，每日回填；第 8 天定稿。>7 天迟到事件不入指标，入原始表留档并监控量级 |
| L2 联网 / L3 运动 | 在线行为，T+1 定稿 |
| 会员/订阅 | 来自计费系统，按其账期定稿（待 R9） |

## 3. 模块一：注册与激活

### 3.1 两条注册曲线 + 前置漏斗

| 指标 | 主键 | 定义 | 角色 |
|---|---|---|---|
| **累计配对激活设备数** | device | 首次完成绑定激活的唯一设备数 | ★ 主口径，gross/net |
| **新增激活设备** | device | 按 first_activation_date 归属，终身一次 | ★ 主口径 |
| App 注册账号数 | user | 完成 App 注册（累计/新增） | 参考曲线 |
| 已绑定激活账号数 | user | 至少绑定 1 台已激活设备 | 账号轨基线，cohort 分母，会员渗透率分母 |

**前置漏斗**：App 注册 → 完成绑定激活的转化与时延；按"注册后 7 天内是否绑定"拆分（买前研究的线索池 vs 绑定失败的开箱问题）。

### 3.2 激活健康

激活率（激活÷售出，分 product_line）、激活时延（中位数+P90）、首次绑定成功率、已售未激活存量池（账龄分布，召回目标）、户均设备数与多机账号占比。

### 3.3 拆分维度

product_line（一级）、国家/地区、渠道、SKU、固件版本、促销活动。

## 4. 模块二：活跃指标

### 4.1 三层活跃（按账号去重，PT 日界）

| 层级 | 名称 | 定义 | 定稿 |
|---|---|---|---|
| L1 | 开机活跃 | 当日账号名下任一设备有开机/唤醒/物理交互 | 近 7 日回填 |
| L2 | 联网活跃 | 当日与云端有效心跳/同步 | T+1 |
| L3 | 运动活跃 | 当日 ≥1 次有效训练（D6） | T+1，**L3 ⊆ L2** |

诊断比值：**运动转化率 L3/L1**（开机却没练=被劝退，最灵敏的产品探针）、**联网健康率 L2/L1**（长期离线=上课转化天花板）、**静默账号**（28 天 L1=0，可召回资产）。

### 4.2 3×3 矩阵

|  | DAU | WAU（滚动7日） | MAU（滚动28日） |
|---|---|---|---|
| L1 开机 | DAU-PowerOn | WAU-PowerOn | MAU-PowerOn |
| L2 联网 | DAU-Connected | WAU-Connected | MAU-Connected |
| L3 运动 | DAU-Workout | **WAU-Workout ← NSM-1** | MAU-Workout |

### 4.3 粘性、频次与分层

- 主用 WAU/MAU 与周均有效训练次数；周频次分布直方图（0/1/2/3/4/5+）。DAU/MAU 不与社交产品对标。
- 近 28 天分层：Power ≥12 次 / Regular 4–11 / Light 1–3 / Dormant（有开机无训练）/ Churned。月度迁移桑基图。**Power 层是产品成功的最硬指标，也是 Pro 会员的天然候选池。**

## 5. 模块三：Cohort 与留存（周 + 月）

- 周 cohort（前期主用）：首次激活 ISO 周分组，W1/W2/W4 留存；**周 cohort × 固件版本 = OTA 效果评估核心视图**。样本 <100 灰显，看趋势不看单点。
- 月 cohort：长期趋势，需 3+ 月数据。
- 起点 = 账号首次绑定激活日。三层各一条留存曲线；L1 高 L3 断崖 = 还在开机但不练了（内容耗尽/进步停滞）。
- 下钻：product_line/国家、激活时固件 × 当前固件、渠道、**首周训练次数（最重要）**、首课类型、户均设备数、**会员状态（会员 vs 非会员留存差 = 会员价值的直接量化）**。
- **Aha Moment**：首周行为 × W12 留存相关性，找阈值 →"首周 ≥N 次训练"大概率是答案 → 变成可执行的前导指标目标。
- **Growth Accounting**：周/月两粒度，Quick Ratio = (New+Resurrected)/Churned，逼近 1 而总量在涨 = 靠新销量填流失坑。放高管首屏。
- **复活**：设备还在家里，沉默 ≠ 流失。复活率、复活后二次留存、沉默时长分布。

## 6. 模块四：上课与运动指标

### 6.1 有效训练（D6 定案）

> **单次训练会话完成 ≥1 个完整组，或训练时长 ≥1 分钟。**

「完整组」判定待 R4；时长建议用有效运动时长（扣暂停/挂机），首期拿不到先用会话时长并在字典注明。门槛低是刻意的（微课不应被排除），质量靠下层指标把关。

### 6.2 活跃质量

单次组数分布（1/2–3/4+）、单次时长分布（<5/5–15/15–30/30+ min）、周人均组数与有效时长、**深度训练占比**（≥2 组且 ≥5 分钟）、组完成率（低=太难在劝退）、volume 与强度进步率（待 R7）、连续周 Streak（≥8 周几乎不流失）。

### 6.3 课型

WORKOUT（20–30min）/ MINI（5–10min）/ MICRO（1–2min，one set/跳绳）。分开统计不做课次加总；合并视角用有效时长/组数加权；**课型 Mix 单独观察**（微课进阶到大课 vs 大课退坡到微课，两个完全不同的故事）。

### 6.4 上课与内容指标

Starts/Completions、完成率（按课型按单课）、平均完成度、人均课次、Time to First Workout、首课完成率；Top/Bottom 课程排行、复练率、**内容库消耗速度**（分 product_line；高消耗用户 >70% 的规模与留存 = 会员流失头号前置信号）、新课采纳曲线、**Pro 独占内容的使用率（待 R10，付费价值验证）**。

### 6.5 核心运动指标

**周均有效训练次数**（频次→习惯→留存→续费）；**训练依从性 Adherence** = 实际训练周数/激活以来总周数（滚动 12 周）。

## 7. 模块五：订阅会员业务看板（D9/D11 定案）

> 完整口径见数据字典 §A4（会员状态机）与 §M5（指标 E01–E18）。要点：

- 状态机：`FREE →(绑定 ATOM)→ PLUS（终身免费）→ PRO_GIFT（套装赠 1–12 个月）→ PRO_PAID（自费）`，到期回落 PLUS。
- **Plus 不是转化指标**（随设备自动发放）；会员生意的全部看点在 Pro。
- **NSM-2 = 活跃付费 Pro 数**（不含赠送期）；配套：Pro 在期渗透率、付费渗透率。
- **赠转付转化率（E05）是会员漏斗第一指标**，按赠送月数（1/3/6/12）× 套装 SKU 分组——不同赠送时长天然是一组定价实验；前导指标是赠送期内的训练活跃与权益用量（E18）。
- 权益即指标：AI 时长配额触顶（Plus 触顶池 = 升级名单）、视频存储、高阶功能使用率（Pro 不用权益 = 流失高危）。
- 续费率（首次/二次）、主动取消 vs 支付失败、cancel_pending 占比（流失先行）、低活跃付费池 / 高频 Plus 池。
- 数据管道独立：订单系统事件流 → `agg_membership_daily`，与 `agg_user_daily` 按 user_id join 做交叉分析。

## 8. 模块六：设备健康（支撑层）

在线率/掉线时长、固件版本分布、OTA 覆盖率与升级成功率（按周，与周 cohort 联动）、配网成功率及失败原因、传感器异常与 RMA（按批次/SKU）、数据完整性监控（**开机补传延迟分布——7 天窗口内的分布形态 + 超窗口丢弃量监控**、上报缺失率）。

## 10. 数据模型与埋点

### 10.1 模型

```
dim_user               user_id, signup_at, signup_source, region, product_line
dim_device             device_id, sku, product_line, firmware, channel, sold_at,
                       first_activated_at, is_returned
bridge_user_device     user_id, device_id, bound_at, unbound_at
dim_content            content_id, type(WORKOUT/MINI/MICRO), duration, product_line,
                       required_tier(FREE/PLUS/PRO)          ← R10 权益边界
dim_plan               plan_id, tier(PLUS/PRO), billing_cycle, price, currency, region

fct_app_registration / fct_device_activation
fct_device_power_on    双时间戳 + 幂等 event_id（7 天补传窗口）
fct_device_heartbeat
fct_workout_session / fct_set(reps, resistance, is_complete)
fct_subscription_event 订阅事件流（§7.7），独立管道入仓

agg_user_daily         ★ 底座一：user_id × date(PT)：三层活跃 flag、各课型 session、
                         有效训练数、时长、组数、绑定设备数快照
agg_membership_daily   ★ 底座二：user_id × date × tier × is_cancel_pending
agg_device_daily       设备级活跃 + 固件（硬件团队）
```

> 账号级活跃/留存/cohort 只从 `agg_user_daily` 派生；订阅指标只从 `agg_membership_daily` 派生；交叉分析 = 两底座按 user_id × date join。口径一致性的关键。

### 10.2 埋点要点

双时间戳（device_local_ts + server_received_ts）+ 幂等 event_id；**`set_completed` 埋点第一优先级**（D6 依赖）；固件补传策略按 7 天窗口约定（D8），超窗事件服务端留档不入指标。
