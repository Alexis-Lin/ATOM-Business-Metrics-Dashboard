# Atom 商业业绩指标框架 v0.1

> 目的：为 Atom（智能硬件 + 软件订阅）搭建一套管理层可用的指标体系与数据看板。
> 本文先定"要看什么、为什么看、怎么定义"，口径细节留待逐条对齐。
> 状态：草案，待业务方确认背景假设（见 §1）。

---

## 0. 先说结论

### 0.1 这套看板要回答的三个问题

整个指标体系不是指标的堆砌，而是服务于三个递进的商业问题：

| # | 问题 | 本质 | 一句话判据 |
|---|---|---|---|
| Q1 | **卖得动吗？** | 硬件生意 | 出货量、激活率、渠道结构、退货率 |
| Q2 | **用得住吗？** | 产品价值 | 留存曲线是否 flatten（是否存在稳定的长期留存平台）|
| Q3 | **赚得回吗？** | 商业模型 | 硬件毛利 + 订阅 LTV 是否 > CAC，且回本周期可接受 |

**Q2 是核心。** 硬件公司最典型的失败模式不是卖不动，而是"卖得动但用不住"——设备在客厅吃灰，订阅到期不续，复购和口碑推荐归零，获客成本永远降不下来。所以留存与持续使用是这套看板的重心，也是你提的注册/活跃/上课/运动四块数据真正要支撑的判断。

### 0.2 建议的 North Star 指标

单一北极星容易失真，建议用一对指标互相牵制：

- **NSM-1（价值）：周有效训练设备数 WAU-Workout**
  = 自然周内至少完成 1 次「有效训练」的设备数。
  为什么用周不用日：健身产品用户天然不是每天练，DAU 会系统性偏低且噪声大；行业惯例以周为习惯周期。
- **NSM-2（变现）：活跃付费订阅数 / MRR**
  = 处于付费有效期内的订阅数（不含试用期）。

配套一个健康度比值：**订阅渗透率 = 活跃付费订阅数 / 累计激活设备数**。这个数字直接告诉你"硬件用户到底愿不愿意为软件付钱"。

### 0.3 一条主线：把整个生意串成一个漏斗

```
生产/发货  →  售出  →  激活注册  →  首次训练  →  形成习惯  →  长期留存  →  订阅转化  →  续订/推荐
   ↓          ↓         ↓            ↓            ↓             ↓            ↓           ↓
 供应链     销售        激活率      Aha 时刻    首月频次      M3/M6 留存   Trial→Paid   续订率/NPS
```

每一段都有一个转化率和一个时延。看板的骨架就是这条漏斗，其余所有指标都是对某一段的下钻。这也是我建议的高管首屏布局。

## 1. 需要你澄清的背景问题

这些答案会直接改变指标口径和数据模型，优先级从高到低：

### P0 — 不确认就没法定义主键和口径

1. **统计主键是设备还是人？**
   一台 Atom 是否支持多个家庭成员账号（profile）？一个账号能否绑定多台设备？
   这决定了 DAU 的主键是 `device_id` / `user_id` / `profile_id`，以及"注册数"到底是设备数还是用户数。
   *我的默认假设：以 `device_id` 为主键做设备侧指标，以 `user_id` 为主键做订阅/变现指标，两套并行。*

2. **商业模式的具体形态？**
   - 硬件是买断制还是硬件+订阅捆绑（含硬件补贴）？
   - 订阅是月付/年付？价格？
   - 是否随机赠送试用期（几个月）？试用期到期是自动转付费还是主动转化？
   - 不订阅的用户还能用设备吗？能用到什么程度（免费档能上什么课）？
   *这决定了变现漏斗怎么画，以及"付费"的分母是什么。*

3. **销售渠道与销售数据可得性？**
   DTC 官网 / Amazon / 线下零售 / 经销商分销？
   **能否拿到"售出"数据（而不只是"发货"数据）？**
   如果只有发货没有 sell-through，激活率的分母就只能用发货量，会系统性低估（渠道库存被算进分母）。

4. **设备离线能用吗？离线数据补传吗？**
   - 断网状态下能否上课？
   - 离线训练记录会在联网后补传吗？补传的最大延迟窗口是多久？
   *这是"机活跃 vs 联网活跃"差异的根源，也决定了 T+1 报表要不要做回溯重跑（backfill）——如果补传窗口是 7 天，那今天的 DAU 数字在 7 天后还会变，报表必须支持重跑并标注"数据未定稿"。*

5. **时区口径？**
   设备是否跨时区销售？"日"按用户本地时区还是统一 UTC/北京时间？
   *建议：面向业务的活跃/训练指标用**设备本地时区**（"用户的今天"），面向财务的订阅/收入指标用**统一时区**（可对账）。两套并存但必须标注清楚。*

### P1 — 影响指标解读和维度拆分

6. **Atom 到底是什么形态的设备？**
   从"one set""跳绳""组数"推断是力量/综合训练类家庭健身设备。需要确认：
   - 有没有阻力/重量的传感数据？能否算出 volume（组数 × 次数 × 阻力）？
   - 有没有配套手机 App？用户会不会只在 App 上活跃而不碰设备？（如果有，活跃分层要加一层 App 活跃）
   - 内容库规模多大？是否有直播课/教练互动？

7. **退货与 RMA 怎么处理？**
   DTC 硬件通常有 30 天无理由退货。累计注册数要不要扣除已退货设备？
   *建议：同时提供 `gross_registered` 和 `net_registered`（扣退货/换机），默认展示 net，避免高管看到的累计数虚高。*

8. **看板给谁看？**
   CEO/董事会（月度、趋势、结论）、增长团队（日度、渠道、可操作）、内容团队（课程级）、硬件团队（固件、联网、故障）——受众不同，看板的层级和刷新频率不同。
   *建议：一个统一数据底座 + 5～6 个分角色 Tab，见 §7。*

9. **现在的数据基础设施是什么？**
   埋点方案（自研 / Amplitude / Mixpanel / Segment）、数仓（BigQuery / Snowflake / ClickHouse / 无）、BI 工具（有没有已在用的）？
   *这决定了是"接现有数据做看板"还是"先补埋点"。多数硬件公司在这一步会发现：想要的指标缺埋点，需要固件配合发版才能拿到，前置期 1～2 个月。*

10. **历史数据能回溯多久？**
    Cohort 分析至少需要 6～12 个月的历史才有意义。如果埋点是新加的，第一版看板只能先跑"新 cohort"，老数据可能永远补不回来——这个预期要提前和管理层对齐。

## 2. 指标体系总览

四层结构，从上到下越来越细：

| 层 | 名称 | 回答的问题 | 主要受众 | 刷新 |
|---|---|---|---|---|
| A | **商业层 Commercial** | 卖了多少？赚了多少？ | CEO / 董事会 / 财务 | 日 + 月定稿 |
| B | **激活层 Adoption** | 卖出去的设备被用起来了吗？ | 增长 / 运营 | 日 |
| C | **参与与留存层 Engagement** | 用户在持续使用吗？用得深吗？ | 产品 / 内容 | 日 + 周 cohort |
| D | **变现层 Monetization** | 用户愿意持续付钱吗？ | CEO / 财务 / 增长 | 日 + 月 |

外加一个支撑层：

| E | **设备健康层 Device Health** | 设备本身是否正常在线？ | 硬件 / 固件 / 客服 | 日 |

## 3. 模块一：注册与激活

### 3.1 核心指标

| 指标 | 定义 | 备注 |
|---|---|---|
| 累计激活设备数 (Cumulative Activated Devices) | 历史上首次成功完成绑定/开机激活的唯一设备数 | 分 gross / net（扣退货停用）|
| 新增激活 (New Activations) | 按 `first_activation_date` 归属的日/周/月新增 | **一台设备终身只计一次**，重置/换绑不重复计入 |
| 激活率 (Activation Rate) | 累计激活设备 / 累计售出设备 | 硬件公司最关键的健康指标之一。健康区间通常 >85%，低于 70% 说明开箱体验或渠道库存有问题 |
| 激活时延 (Time to Activation) | 购买/发货 → 首次激活的天数，看中位数和 P90 分布 | 长尾（>30天未激活）是"礼物/囤货/退货"信号，值得单独拉名单 |
| 首次绑定成功率 | 激活流程进入 → 完成的转化 | 开箱体验的直接度量，掉的每一个百分点都是白花的获客成本 |

### 3.2 必备的拆分维度

所有注册指标至少支持这几个维度切片：

- **渠道** channel：DTC / Amazon / 线下 / 经销商
- **地区** region：国家 / 州省（也用于时区归属）
- **SKU / 硬件版本**：不同型号的激活率差异往往能直接暴露某一批次的质量问题
- **固件版本** firmware_version
- **是否随附订阅/促销活动** campaign
- **激活来源**：App 引导 / 设备端自助

### 3.3 一个容易被忽略的指标

**「已售未激活」存量池 (Sold-Not-Activated Backlog)**：售出但从未激活的设备数及其账龄分布。
这是一笔"已经花了 CAC 但零价值"的沉没资产，也是最容易见效的召回目标（发货邮件/短信提醒激活）。多数硬件公司从不看这个数，但它常常有两位数百分比。

## 4. 模块二：活跃指标

### 4.1 三层活跃定义（你提的三个维度，我给一套严谨口径）

这三层是**逐层收窄的包含关系**，差值本身就是最有价值的诊断信号：

| 层级 | 名称 | 定义 | 衡量什么 |
|---|---|---|---|
| **L1** | 机活跃 Device-On Active | 当日设备有开机 / 唤醒 / 任意物理交互事件（可离线产生，补传后计入）| 设备在物理上被"碰过"，衡量存在感 |
| **L2** | 联网活跃 Connected Active | 当日设备与云端有过有效心跳或数据同步 | 可触达性——影响 OTA 覆盖、内容下发、消息推送、以及数据本身的可信度 |
| **L3** | 训练活跃 Workout Active | 当日完成 ≥1 次**有效训练**（定义见 §6.1）| **真正的产品价值**，也是 North Star 的基础 |
| (L0) | App 活跃 App Active | 当日 App 有有效会话 | *仅当有配套 App 时启用* |

**衍生诊断指标（比绝对值更有用）：**

- **训练转化率 = L3 / L1**：开了机的设备里，有多少真的练了？
  这个比值低，说明用户"想练但被劝退了"——可能是开机慢、找课难、课程不合适。这是产品体验最灵敏的探针之一。
- **联网健康率 = L2 / L1**：开机了但没联网的设备占比。
  持续偏高说明有 Wi-Fi 配网/掉线问题，会同时污染你所有的云端数据。
- **静默设备 = 已激活 且 近 28 天 L1 = 0**：物理沉默，但设备还在用户家里，是可召回资产。

### 4.2 时间维度：3 × 3 矩阵

三层活跃 × 三个时间窗，共 9 个数字。这是看板"活跃"页的核心表格：

|  | DAU（日）| WAU（滚动 7 日去重）| MAU（滚动 28 日去重）|
|---|---|---|---|
| **L1 机活跃** | DAU-Device | WAU-Device | MAU-Device |
| **L2 联网活跃** | DAU-Connected | WAU-Connected | MAU-Connected |
| **L3 训练活跃** | DAU-Workout | **WAU-Workout ← NSM** | MAU-Workout |

口径约定：
- **用滚动 28 天而非自然月**做 MAU，避免月份天数差异造成的锯齿；自然月版本单独出，供财务对账。
- WAU 用滚动 7 天；同时保留"自然周"版本供周报使用（自然周的定义要固定，建议 ISO 周，周一起算）。
- 去重主键 = `device_id`（如需人维度，另出一套 `user_id` 口径）。

### 4.3 粘性与频次

- **Stickiness = DAU / MAU**：注意——健身产品这个数天然低（每周练 3 次的模范用户 DAU/MAU 也只有 ~43%）。**不要拿社交产品的基准来对标**，容易得出错误结论。
- **更适合健身产品的粘性指标：WAU / MAU**（一个月内活跃的用户里，本周还在练的比例）和 **周均训练频次 (Workouts per Active Device per Week)**。
- **周频次分布直方图**：0 / 1 / 2 / 3 / 4 / 5+ 次的人数分布。比均值有用得多——均值 2.1 次可能是"大家都练 2 次"，也可能是"一半人不练、一半人练 4 次"，这两种情况的经营策略完全相反。

### 4.4 用户分层（管理层看一张图就够）

按最近 28 天的训练频次把活跃设备分档，看每月的人数流转：

| 分层 | 定义（近 28 天）|
|---|---|
| **Power** | ≥12 次（约 ≥3 次/周）|
| **Regular** | 4～11 次（约 1～2 次/周）|
| **Light** | 1～3 次 |
| **Dormant** | 0 次训练，但有开机/联网 |
| **Churned** | 0 次任何活跃 |

用桑基图或堆叠面积图展示每月分层间的迁移。**Power 层的绝对数和占比，是判断产品是否真正成功的最硬指标**——它代表有多少人把 Atom 变成了生活习惯。

## 5. 模块三：Cohort 与留存分析

### 5.1 基础 Cohort 设计

- **Cohort 定义**：按**首次激活月份**（或周）分组。
  *为什么不按购买月：激活时延波动大，按激活分组才能公平比较"用了 N 个月之后"的表现。*
- **留存口径**（两种都要，用途不同）：
  - **Classic Retention（区间留存）**：第 N 个月内是否有过活跃 → 用于长期趋势判断，波动小，适合管理层。
  - **N-Day Retention（精确日留存）**：第 N 天当天是否活跃 → 用于 onboarding 优化，D1/D7/D30 三个关键点。
- **每种活跃定义各出一条留存曲线**：L1 留存 / L2 留存 / **L3 训练留存（最重要）**。
  三条线的分叉点很有信息量——如果 L1 留存高但 L3 留存断崖，说明"设备还在用，但已经不训练了"，通常是内容耗尽或进步停滞。

### 5.2 关键的下钻维度

Cohort 热力图必须支持按这些维度切分，因为**差异本身就是行动线索**：

| 维度 | 想验证什么 |
|---|---|
| 渠道 | 哪个渠道来的用户质量高？（Amazon 冲动购买 vs DTC 主动搜索，留存往往差很多）|
| 地区 / SKU / 固件 | 有没有区域性或批次性问题 |
| 是否订阅 | 订阅用户 vs 非订阅用户的留存差 → 直接量化订阅的价值 |
| **首周训练次数（0 / 1-2 / 3+）** | **这是最重要的一条** |
| 首课类型（大课 / 短课 / one set 起步）| 哪种入门路径留存更好 → 直接指导 onboarding 默认推荐 |
| 是否完成 onboarding 引导 | 引导流程的长期价值 |

### 5.3 找到 Aha Moment

具体方法：把首周（激活后 7 天内）的行为变量与 M3 留存做相关性分析，找出那个"跨过就留下、跨不过就流失"的阈值。

健身品类的经验规律是 **"首周完成 N 次训练"** 这个变量的解释力最强。假设分析结果是"首周 ≥3 次训练的用户，M3 留存 62%；<3 次的只有 18%"——那么产品团队接下来一个季度的唯一目标就非常清晰了：**把首周 ≥3 次的用户占比从 X% 提到 Y%**。

这是整套看板最有价值的一个产出：把"提升留存"这个空泛目标，翻译成一个可执行、可归因、可追踪的前导指标。

### 5.4 Growth Accounting（增长归因）

每月把 WAU/MAU 的变化拆成四个分量，解释"增长到底从哪来"：

```
本月活跃 = 上月活跃
         + New（本月首次激活且活跃）
         + Resurrected（沉默 ≥28 天后回归）
         - Churned（上月活跃、本月完全沉默）
```

同时看 **Quick Ratio = (New + Resurrected) / Churned**。
> 判读：**> 1 才是净增长**。如果 MAU 在涨但 Quick Ratio 逼近 1，说明增长完全靠新设备销售在填流失的坑——一旦销售放缓，活跃盘会立刻塌方。这是硬件+订阅公司最危险、也最容易被"总量在涨"掩盖的信号。**建议把 Quick Ratio 直接放在高管首屏。**

### 5.5 复活（Resurrection）

硬件产品相比纯软件的独特优势：**设备还在用户家里**，沉默用户是可召回的存量资产，而不是彻底流失。

- 复活设备数 / 复活率（沉默 ≥28 天的设备中，本月回归的比例）
- 复活后的二次留存（复活用户能待多久？如果复活后又立刻沉默，说明召回动作只是打扰，没解决根因）
- 沉默时长分布（沉默 1 个月 vs 6 个月的可召回性差异巨大，决定召回资源怎么投）

## 6. 模块四：上课与运动指标

### 6.1 先定义"有效训练"（这是最需要和你敲定的一条）

几乎所有下游指标（L3 活跃、留存、频次、North Star）都建立在这个定义上，所以它必须先定死。

**我的建议口径：**

> **有效训练 (Qualified Workout)** = 单次训练会话中，满足以下任一条件：
> 1. 完成 ≥ 2 个**完整组**（set 内动作次数达到该课程设定的下限）；**或**
> 2. **有效运动时长** ≥ 5 分钟（仅计传感器检测到实际运动的时间，不含休息和暂停）。

设计理由：
- **用"完整组"而非"时长"作为第一判据**——时长会被"开着课去做别的事"污染，组数是真实的努力证据。
- **门槛不能太高**：跳绳/one set 这类 1～2 分钟的微课，本身就是为了降低启动门槛、维持习惯连续性而设计的。如果门槛定到"必须练满 10 分钟"，会系统性低估微课的价值，进而误导产品决策（可能会砍掉实际上最能维持习惯的功能）。
- **也不能太低**：单纯开机、点开课程、练 10 秒就退出，不能算训练——否则活跃数虚高，留存曲线失真。

**建议同时保留三档口径**，在看板上可切换，避免单一定义带来的误判：

| 档位 | 定义 | 用途 |
|---|---|---|
| **Loose** | 任意 session 开始 | 看兴趣/意图，诊断"打开了没练完" |
| **Qualified（默认）** | ≥2 完整组 或 ≥5 分钟有效运动 | **所有对外/对上口径的默认值** |
| **Strict** | 完成度 ≥ 80% 的课程 | 看内容质量与深度参与 |

### 6.2 课程类型口径

| 类型 | 时长 | 代号 | 说明 |
|---|---|---|---|
| 大课 Workout | 20～30 min | `WORKOUT` | 主力内容，价值感强 |
| 短课 Mini Workout | 5～10 min | `MINI` | 主力习惯维持工具 |
| 微课 One Set / 跳绳 | 1～2 min | `MICRO` | 碎片化，降低启动门槛 |

**注意：不要只用总课次做 KPI。** 三种课型的一次不等价——1 次微课 ≠ 1 次大课。建议：
- 三种课型的指标**分开展示**，不做简单加总；
- 如需一个合并指标，用**有效运动时长**或**总容量**做加权，而不是课次；
- 增加 **课型 Mix（三类课次的占比结构）** 作为一个独立观察对象。

### 6.3 上课指标清单

按课型 × 时间维度全部提供：

| 指标 | 定义 |
|---|---|
| Session Starts | 课程开始次数 |
| Session Completions | 课程完成次数（达到课程结束或完成度 ≥ 阈值）|
| **Completion Rate** | Completions / Starts。**按课型和单课分别看**，是内容质量最直接的度量 |
| 平均完成度 | 实际完成部分 / 课程总长（%），比二值的完成率信息量更大 |
| 人均课次 | 总课次 / 活跃设备数（按日/周/月）|
| **课型 Mix** | 三类课次的占比结构及其随生命周期的变化 |
| Time to First Workout | 激活 → 首次有效训练的时长（中位数 / P90）|
| 首课完成率 | 第一次上课就完成的比例——第一印象，与长期留存强相关 |

### 6.4 内容侧指标（给内容团队）

| 指标 | 为什么重要 |
|---|---|
| Top / Bottom 课程排行（按开始数、完成率、复练率）| 指导内容排期，砍掉低完成率课程 |
| 课程复练率 | 用户愿意重复练的课 = 真正的好内容 |
| **内容库消耗速度 (Content Exhaustion)** | 用户已练过的内容占可用内容库的比例。**这是订阅流失的头号前置信号**——"没有新课练了"是健身订阅最常见的退订理由。需要监控"高消耗用户"（已练完 >70% 内容）的规模和他们的留存表现 |
| 新课上线后的采纳曲线 | 内容更新到底有没有拉动活跃 |
| 教练/品类维度的表现 | 内容策略与选品 |

### 6.5 运动质量指标（你问的"运动指标"，我的建议）

**核心推荐指标：周均有效训练次数 (Workouts per Active Device per Week)**

理由：健身产品的留存不由"单次练多久"驱动，而由**频次**驱动——频次决定习惯是否形成，习惯决定留存，留存决定订阅续费。一个每周练 3 次 × 10 分钟的用户，价值远高于每两周练 1 次 × 60 分钟的用户。频次是这条因果链上最靠前、最可干预的杠杆。

**完整指标集：**

| 指标 | 定义 | 说明 |
|---|---|---|
| **周均有效训练次数** | 有效训练次数 / 活跃设备数 / 周 | ★ 核心运动指标 |
| 有效运动时长 | 传感器判定为实际运动的秒数（不含休息/暂停）| 与 Session Duration 分开报——后者会被挂机严重污染 |
| Session Duration | 从开始到结束的挂钟时长 | 仅作参考 |
| 完整组数 Completed Sets | 达到动作次数下限的组数 | 你提的"是否完整完成 1~2 个组"就落在这里 |
| 总次数 Reps | 有效动作次数 | |
| **训练容量 Volume** | Σ(reps × 阻力/重量) | *需确认有阻力传感数据。* 力量训练的"努力度"黄金指标 |
| **强度进步率** | 人均 volume 或平均阻力的月环比 | **"我在变强"是最强的留存驱动力**，也是最好的营销素材和续订理由 |
| 连续周 Streak | 连续有 ≥1 次有效训练的周数，看分布 | Streak ≥8 周的用户几乎不流失 |
| 组完成率 | 完整组 / 开始的组 | 训练难度是否设置合理（组完成率持续偏低 = 课程太难，劝退）|

### 6.6 一个建议增加的复合指标

**训练依从性 (Adherence Rate) = 实际训练周数 / 加入以来的总周数**（滚动 12 周窗口）

这是健身/健康行业的通用指标，好处是**天然可跨 cohort 比较**，不受用户注册早晚影响，可以直接作为"产品是否让人坚持下来"的单一答案。

## 7. 模块五：变现与订阅（补充，但对"评估商业业绩"必需）

你的需求里没展开这块，但既然目标是"评估商业业绩"和"判断产品是否成功"，变现层不能缺——否则看板只能回答"用户在用吗"，回答不了"这门生意成立吗"。

### 7.1 订阅漏斗

```
激活设备 → 开通试用 → 试用期内活跃 → 试用转付费 → 首次续订 → 长期续订
```

| 指标 | 说明 |
|---|---|
| Attach Rate | 激活设备中开通订阅（含试用）的比例 |
| Trial Start Rate / Trial→Paid 转化率 | 试用转化是变现漏斗最关键的一跳 |
| **试用期活跃度 vs 转化率的相关性** | 试用期练够 N 次的用户转化率是多少 → 直接指导试用期的运营干预 |
| 活跃付费订阅数 | 处于付费有效期内（NSM-2）|
| MRR / ARR、ARPU | 月付年付要分开看，年付的现金流和留存特征完全不同 |
| 订阅 Churn Rate（月度/年度）| 主动退订 vs 被动流失（支付失败）**必须分开**——后者靠 dunning 挽回，是最便宜的收入 |
| 续订率（首次续订 / 二次续订）| 首次续订率是订阅生意的生死线 |
| **LTV** | 硬件毛利 + 订阅生命周期价值 |
| **LTV / CAC 与回本周期 (Payback Period)** | 最终判据。硬件公司常见问题是回本周期长于订阅生命周期——意味着规模越大亏得越多 |

### 7.2 硬件商业指标

出货量、销售额、退货率（分渠道）、毛利率、库存周转、RMA 率与故障类别。

### 7.3 交叉洞察（最有价值的部分）

- **订阅 vs 非订阅用户的活跃/留存差**（量化订阅的实际价值）
- **训练频次 vs 续订率的关系**（"每周练 ≥2 次的用户续订率 X%，<1 次的只有 Y%"）→ 把留存指标直接和收入挂钩，这是说服管理层投资产品体验的最有力证据
- **退订前 4 周的行为衰减曲线** → 构建流失预警模型，提前 2～4 周识别高危用户并干预

## 10. 数据模型与埋点

### 10.1 星型模型草案

**维度表**
```
dim_device       device_id, sku, firmware_version, channel, region, timezone,
                 sold_at, shipped_at, first_activated_at, is_returned, returned_at
dim_user         user_id, signup_at, region, locale
dim_profile      profile_id, device_id, user_id            -- 若支持家庭多成员
dim_content      content_id, type(WORKOUT/MINI/MICRO), duration_sec,
                 coach, category, difficulty, published_at
dim_date         date, iso_week, month, quarter, is_holiday
```

**事实表**
```
fct_device_registration     一台设备一行，激活生命周期事件
fct_device_heartbeat_daily  device_id × date，含 is_power_on / is_connected
fct_workout_session         一次训练会话一行 ← 核心事实表
fct_set                     每一组一行（最细粒度，支撑组数/reps/volume）
fct_subscription_event      订阅状态变更流水（start/trial/convert/renew/cancel/fail）
fct_order                   订单/退货
```

**聚合表（看板直接查询，保证响应速度）**
```
agg_device_daily            ★ device_id × date 的宽表，所有活跃/留存/cohort 的唯一底座
                            字段：三个活跃 flag、各课型 session 数、有效训练数、
                                  有效运动时长、完整组数、reps、volume、订阅状态快照
agg_cohort_retention        cohort_month × period_n × 活跃口径 × 拆分维度
agg_content_daily           content_id × date
```

> **设计要点**：所有活跃、留存、cohort、分层指标全部从 `agg_device_daily` 这一张表派生。
> 这是保证"不同页面的数字能对上"的关键——一旦允许各个报表各自从原始事件表计算，口径漂移是必然的。

### 10.2 建议的埋点事件清单

| 事件 | 关键属性 | 用途 |
|---|---|---|
| `device_activated` | device_id, user_id, channel, sku, fw_ver, ts | 注册 |
| `device_power_on` | device_id, ts, is_offline | L1 机活跃 |
| `device_heartbeat` | device_id, ts, rssi, fw_ver | L2 联网活跃 |
| `workout_session_start` | session_id, content_id, type, ts, profile_id | 上课 |
| `workout_session_end` | session_id, end_reason(complete/quit/timeout), completion_pct, active_duration_sec, total_duration_sec | 完成率 |
| `set_completed` | session_id, set_index, reps, resistance, is_complete, active_sec | 运动指标 ★ |
| `subscription_event` | user_id, event_type, plan, price, currency, ts | 变现 |
| `onboarding_step` | device_id, step, status | 开箱漏斗 |
| `wifi_setup` | device_id, attempt_n, result, error_code | 配网成功率 |

**埋点原则：**
1. 每个事件必须带 `device_local_ts` 和 `server_received_ts` 两个时间戳 —— 离线补传场景下，这是唯一能正确归属"哪一天"的办法。
2. 事件需带幂等 `event_id`，补传会产生重复，必须去重。
3. `set_completed` 是最重要也最容易漏的埋点 —— 你提的"是否完整完成 1~2 个组"完全依赖它，需要固件侧配合。**如果这个埋点现在没有，它应该是第一优先级。**

## 12. 口径治理（这条比看板本身更重要）

一套指标体系失败，几乎从不是因为图表不够漂亮，而是因为**同一个指标在不同场合数字不一样**，最后所有人都不信这份数据。

建议做三件事：

1. **建立指标字典 (Metric Dictionary)** 作为 single source of truth。每个指标记录：名称、业务定义、SQL 口径、主键、时区、更新频率、Owner、变更历史。**看板上的每个数字都能点进去看到它的定义。**
2. **口径变更走版本管理**。任何口径调整必须重算历史并在图表上打标注（"2026-09-01 起 '有效训练' 门槛由 3 分钟调整为 5 分钟"）。否则半年后没人能解释某次趋势跳变是产品变化还是口径变化。
3. **数据未定稿状态显式标注**。受离线补传影响，近 N 日数据会变化。看板必须区分「未定稿」和「已定稿」，避免管理层拿着未定稿数字做决策。
